# AI Usage Report

## AI Tools Used
Gemini (Antigravity IDE assistant) — used throughout development for code generation, architecture planning, and debugging.

## What I Asked AI To Do

1. Generate the Spring Boot project structure including entity classes, repository interfaces, service implementations, and controller classes based on the requirements.
2. Generate Flyway migration SQL scripts for the full database schema with correct foreign keys and indexes.
3. Generate the React/TypeScript frontend components including the ticket detail page, dashboard pages, and form validation schemas.
4. Generate the JWT authentication filter and Spring Security configuration.
5. Generate the SLA calculation logic and ticket state machine implementation.
6. Generate seed data SQL with realistic ticket states for the development database.
7. Debug compilation errors in MapStruct mapper configurations.
8. Generate test classes for service layer unit tests and MockMvc controller tests.
9. Help write comprehensive documentation including architecture diagrams, product decision rationale, and the demo script.

## Most Useful Prompt
The most effective prompts were those that gave the AI the complete context: entity relationships, business rules, and desired behavior together — rather than asking for one class at a time. Providing the state machine transitions explicitly and asking the AI to enforce them in the service layer produced accurate results.

## Code I Modified
- SLA pause logic: AI initially did not correctly accumulate activeMinutesElapsed across multiple PENDING cycles. I rewrote the activeMinutesElapsed accumulation in the status transition service to correctly handle multiple pending/resume cycles.
- Ticket number generation: AI used a max(id)+1 approach that had a race condition. I replaced it with a PostgreSQL sequence (nextval) approach.
- Internal note filtering: AI initially filtered comments in the controller. I moved the filter to the repository query to ensure backend enforcement regardless of which code path is used.
- Seed data: AI generated simplistic seed data. I added SLA-breached tickets (past slaDeadline), tickets in PENDING_STUDENT state with realistic pending reasons, and a spread of creation dates to make the ageing dashboard meaningful.

## AI Output That Was Wrong
The AI initially generated the JWT implementation using the deprecated jjwt 0.9.x API (using `Claims claims = Jwts.parser().setSigningKey(secret).parseClaimsJws(token).getBody()`). The project uses jjwt 0.12.x which has a different API.

## How I Identified The Problem
Compilation failed with method not found errors on `setSigningKey` and `parseClaimsJws`. I checked the jjwt 0.12.x migration guide.

## How I Fixed It
Updated to the 0.12.x API: `Jwts.parser().verifyWith(key).build().parseSignedClaims(token).getPayload()` and used `Keys.hmacShaKeyFor(secret.getBytes())` for key construction.
